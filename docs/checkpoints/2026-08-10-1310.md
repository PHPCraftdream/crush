Round 4's fixes, in detail:
- **Lease-renewal loop** added to `executeEntry`: a ticker at `leaseTTL/3` calls
  a new `RenewRunQueueLease` SQL query (scoped to `status=leased AND
  leased_by=?`) for as long as `Coordinator.Run` is in flight, keeping a
  long-running execution's row genuinely `leased` so `CleanupExpiredLeases`
  can't reap it out from under a still-running turn.
- **`ErrCallQueuedNotExecuted` redesigned twice within this round**: a first
  attempt (single `RenewRunQueueLease` call) was written, then DISPROVEN by an
  isolated debug test before being trusted — the renewal happened almost
  instantly after the original lease, so it barely extended the deadline
  beyond what leasing already set, and `CleanupExpiredLeases` still reaped the
  row (charging an attempt) after one ordinary TTL window, same as doing
  nothing. The actual fix: immediate `NackRunQueueEntryNoAttemptPenalty`
  release (mirrors `SessionLockBusyError`'s handling, never counts an attempt)
  paired with a new in-memory `RunQueuePump.busyBackoffUntil` per-session
  deadline preventing THIS pump instance from re-attempting too soon (a
  different process is free to try immediately — no reason to block it).
- **Self-caught defer-ordering race**: the renewal loop's stop was originally
  a `defer`, which left a window where the renewal goroutine could still be
  alive (and fire once more) while the `ErrCallQueuedNotExecuted` branch had
  already Nacked the row — producing a spurious "lost lease ownership" log
  line. Fixed by stopping the renewal loop synchronously right after
  `Coordinator.Run` returns, before any Ack/Nack/Renew call, not via `defer`.
  Found and fixed by the orchestrator's own re-verification, not by review.
- **`RunQueuePumpConfig.TestLeaseTTL`** test seam added (mirrors `TestTick`) —
  `RunQueueLeaseTTL` (30s) isn't itself overridable, and both bugs needed real
  elapsed time to exercise. Discovered mid-implementation that
  `lease_expires_at` is stored as Unix SECONDS, so a sub-second `TestLeaseTTL`
  is silently truncated to 0 and produces non-deterministic, boundary-
  dependent test behavior — confirmed by an early version of the
  lease-renewal test failing unpredictably before being corrected to use a
  full 1-second TTL. The backoff test has no such constraint
  (`busyBackoffUntil` is in-memory `time.Time`, not a DB column) and uses a
  fast sub-second TestLeaseTTL.
- `internal/app/resolve_session_test.go`'s hand-written `mockSessionService`
  needed the new `RenewRunQueueLease` method — caught only by `go vet ./...`
  across the WHOLE repo, not the touched packages alone.

## Decisions

- **Lease renewal (ticker-based, `leaseTTL/3`) chosen for the active-execution
  case (BLOCKER-1)** — the only mechanism that can keep a row `leased` for an
  unbounded, unknown-in-advance real turn duration.
- **NackRunQueueEntryNoAttemptPenalty + local in-memory backoff chosen over
  lease renewal for the externally-owned case (HIGH-2)**, specifically because
  a single renewal call was PROVEN (via an isolated debug test) not to provide
  any real delay when the call returns near-instantly — renewal only helps
  when there's ongoing work to keep renewing against.
- **Backoff tracked in-memory per pump instance, not in the DB row**, so a
  different process's pump is never blocked by this process's local
  contention — deliberately narrower in scope than the row's actual lease
  state.
- **Renewal-loop stop moved from `defer` to a synchronous call right after
  `Coordinator.Run` returns** — closes a self-found race, not something the
  external review caught; a lesson that continuing to independently re-verify
  fixes (not just trusting they compile and pass the obvious test) keeps
  paying off even after four rounds.
- **`TestLeaseTTL` kept at whole-second granularity for the lease-renewal
  test, sub-second granularity accepted for the backoff test** — because only
  the former touches the DB's Unix-seconds `lease_expires_at` column; the
  latter is purely in-memory.
