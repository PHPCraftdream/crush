**Phase 2 — version string confusion, investigated and fixed (task #79).**
User noticed `crush --version` showed two different-looking "upstream"
numbers in one line. Root-caused (personally, not delegated, since it
required reading Go's own module-versioning behavior): `v0.72.0` is a real
git tag reachable from HEAD (shared history with upstream from before this
fork diverged), so a plain `go build .` on this repo's Go 1.26.3 toolchain

the code's own (now-stale) assumption that plain builds show `"(devel)"`
with no tag to extract. Fixed by removing the baseTag-extraction machinery
entirely rather than patching the trigger condition — the original purpose
(helping a `go install` user see their release line) is superseded by the
deliberate `UpstreamTriagedVersion` watermark added earlier this session.
