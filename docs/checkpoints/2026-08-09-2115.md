## Decisions

- **One unified 13-task set from two overlapping reviews, not two parallel sets** — the reviews' P0-2 framings (duplicate execution vs. data loss) are two branches of the SAME retry-tail code; fixing one naively worsens the other, so tasks were written to explicitly cross-reference both framings and require distinguishing the two failure modes rather than picking one.
- **#337's clobber-window fix: accept the conservative, review-endorsed fallback (no OS-lock reacquire) over either "fully close it" design** — both stronger designs were empirically proven, via the orchestrator's own testing (not sub-agent claims), to cause real self-collision regressions in internal/agent under load. This is a deliberate trade-off, documented in the commit message, not an oversight.
- **`go test ./internal/agent/... -count=2` (full package, no `-run` filter) is now a standing mandatory verification step for any change touching internal/agent's retry/lock code** — codified into every subsequent task's delegation prompt after #337 discovered that isolated/single-run tests cannot catch this class of self-collision regression.
- **Sub-agent never commits; re-delegation into the same `--session` over silent patching, except genuinely trivial one-line/mechanical fixes** (a gofumpt-style violation, a stray sqlc version bump, restoring a revert-checked line) — held without exception this entire session.
- **#340 split into 3 rounds within one task rather than 3 separate tasks** — mechanism-only (round 1+2, committed) vs. call-site migration (round 3, in flight) are different risk profiles; landing the mechanism as its own verified, tested unit before wiring it into the most self-collision-prone code in the codebase was judged safer than a single big-bang round.
