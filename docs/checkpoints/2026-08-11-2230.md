## Decisions

- Established a **hard rule going forward**: never trust a backgrounded
  `go test` task's self-reported exit code alone — always read the log
  file's actual content, or run critical final-verification suites
  synchronously in the same turn. This was learned the hard way after
  discovering two consecutive prior commits (P1-5, P2-2) had silently
  shipped with `go test ./internal/agent/...` build-failing the whole
  time, undetected by exactly this trust shortcut.
- P1-3 (rowid tie-breaker): accepted an architecturally-correct fix whose
  own regression test's revert-check was empirically inconclusive in this
  environment (SQLite's index B-tree already incidentally provides the
  same ordering via implicit rowid appending), rather than engineering an
  artificial way to force a flake — documented the limitation honestly in
  the test and commit message instead of hiding it.
- P2-3 (Codex MCP token): did the live-mechanism verification personally
  (using the actually-installed codex CLI) rather than trusting the
  delegated session's unverified claim, mirroring the standing precedent
  from CS-6 (checking real installed package behavior, not assumptions,
  for exactly this class of "does the CLI actually support X" question).
- Continued the pattern from every task this round: full independent
  zero-trust re-verification of every delegated `/crush` diff before
  committing, including genuine revert-checks (not just re-reading code)
  — this caught real bugs or vacuous tests in the large majority of
  delegated diffs this round (P0-3, P0-4, P1-1, P1-5, P2-2 dead code,
  P2-3 all had real findings; P1-2, P1-3, P1-4 were clean or had only
  minor/honest limitations).
