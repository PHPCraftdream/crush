confirmed the exact real failure, restored, confirmed PASS again):

- **B-1** (`internal/agent/tools/safe.go`, `bash.go`): `env`/`nice`/`nohup`/
  `time`/`timeout` were in `safeCommands`, a prefix-match allowlist that
  skips `permissions.Request` entirely — so `env rm -rf /`, `timeout 10
  ./exfil.sh` etc. bypassed the permission prompt completely since these are
  command-wrappers that execute an arbitrary subcommand. Removed all five
  from the list (kept `printenv` as the safe read-only alternative to bare
  `env`). Extracted the inline matching logic into a testable
  `isSafeReadOnlyCommand` function. New file `safe_test.go`.
- **B-2** (`internal/agent/agentguard/agentguard.go`): the recursion-guard's
  wrapper strip-list only handled `exec`/`command`/`time`/`nohup` — missing
  `env`/`nice`/`timeout` meant `env claude -p ...`, `nice claude ...`,
  `timeout 30 claude ...` all bypassed the recursion guard too (doubly
  dangerous combined with B-1: one invocation bypassed BOTH systems).
  Implemented proper flag-aware stripping (`stripEnvWrapperArgs`,
  `stripLeadingFlags` with per-utility value-flag maps) since `nice`/
  `timeout` have their own leading flags/positional args before the real
  command, unlike the existing bare wrappers. New tests added to the
  existing `agentguard_test.go`.
- **BUG-1** (`internal/agent/tools/download.go`): non-atomic
  `os.Create`+`io.Copy` direct to the final path — a mid-copy network
  failure or ctx-cancel left a truncated file that a later view/edit would
  read as valid. Also no size limit (`io.Copy` unbounded). Fixed with a
  temp-file-then-`os.Rename` pattern (mirrors `fsext.AtomicWriteFile` but
  streaming) plus a new `MaxDownloadBytes` (500 MiB) `io.LimitReader` cap.
  New file `download_test.go` (none existed before).
- **BUG-3** (`internal/agent/cliprovider/provider.go`'s `saveFileParts`):
  two `FilePart`s sharing the same base filename silently overwrote each
  other on disk while both `filePaths` entries kept pointing at the
  now-single, last-write-wins file. Fixed with `usedNames`-tracked
  collision disambiguation (`-N` suffix only when needed, preserving
  original names in the common case) — mirrors `saveAttachmentToDisk`'s
  existing pattern in `internal/server/handlers.go`. New test added to
  `provider_test.go`.
- **BUG-2** (`internal/agent/cliprovider/mcpserver.go`): `registerGeminiMCP`/
  `registerQwenMCP` write under a STABLE per-workingDir server name, so two
  concurrent crush sessions in the same project sharing a CLI provider
  clobber each other's entry (last-register-wins, expected/accepted); the
  ACTUAL bug was that the corresponding `deregisterX` (called via `defer`
  when either session's stream ends) deleted the entry UNCONDITIONALLY,
  even if a later session had since overwritten it — session A finishing
  first could delete session B's still-active registration. Fixed by
  passing the exact url/addr each call registered through to its own
  deregister call, comparing against the currently-stored value, and
  making deregister a safe no-op if they no longer match (i.e. someone
  else now owns the entry). Also removed a now-redundant "deregister then
  immediately re-register" pair at the two registration call sites (was
  always a no-op relative to the final state, since register unconditionally
  overwrites regardless). New file `mcp_dereg_race_test.go`, isolating
  `os.UserHomeDir()` via `t.Setenv` (confirmed safe: `qwenSettingsPath`/
  `geminiSettingsPath` call the stdlib directly, not this repo's own
  process-cached `internal/home.Dir()`, so no package-init-time-caching
  pitfall).
