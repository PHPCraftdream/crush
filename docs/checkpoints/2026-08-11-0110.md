1. **"coder agent configuration is missing" / "coder agent not configured"**
   — `config.Load`/reload only populate the coder agent's config entry
   (`SetupAgents()`) when a provider is already configured at the exact
   moment they run. Several tests (this session's own two `p348_p0_1_*`
   tests, plus pre-existing `TestP1_3_CoordinatorSummarizeSingleRead` and
   `TestP341_ConcurrentSetModelsSummarizeUsesTargetSessionSnapshot`) register
   a provider programmatically AFTER an initial empty `config.Init`, bypassing
   that population entirely. A broad audit found ~20 similar call sites just
   in `internal/agent/coordinator_test.go` alone, so rather than patching
   every test site, fixed at the root: `App.InitCoderAgent` and
   `agent.NewCoordinator` now both self-heal (call `SetupAgents()` and
   re-check on a miss — cheap and side-effect-free). Added two deterministic
   regression tests (`p350_coder_agent_selfheal_test.go` in both `internal/
   agent` and `internal/app`) that force the exact precondition directly
   rather than depending on the unidentified environment leak, so they fail
   reliably without the fix regardless of machine. Committed as `e43c835f`.
2. **"large model not selected"** — surfaced only after fix #1 got past its
   own failure. Same class of gap, one level deeper: those same tests (plus
   this session's own new self-heal regression test) configure a provider
   but never select a model to use with it. Unlike #1, NOT self-healed in
   production code — the real population path

   `internal/cmd/providers_test.go`'s own documented history). Fixed at the
   test level instead: each affected test now gets an explicit
   `SetSelectedModelRuntime` call plus a matching provider `Models` list
   entry, mirroring the working pattern already used by this session's own
   `p348_p0_1_*` tests. Committed as `0d0e4029`.
