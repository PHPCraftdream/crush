## Decisions

- **Strategy: sequential sub-agents via `/crush` (external `crush run` CLI), strictly one task at a time**, chosen over parallel/workflow because every task in this round touches the same core files (`agent.go`, `mailbox.go`, `coordinator.go`, `lock.go`, `handlers.go`) — parallel execution would guarantee git/semantic conflicts. Task #335 (genuinely independent, provider-cancellation contract) was deliberately still placed at the end of the same sequential chain rather than run in parallel, purely to keep execution strictly one-at-a-time as instructed.
- **The sub-agent does NOT commit.** Every `crush run` prompt explicitly instructs "не коммить, не пуш" — the orchestrator (this session) does the zero-trust verification and the actual `git commit` after independently confirming correctness. This is what caught both bugs above; sub-agent self-reports of "revert-check passed" / "tests pass" are treated as claims, not evidence.
- **Re-delegation over silent patching**: when the orchestrator finds a bug in a sub-agent's diff, the fix is NOT applied directly by the orchestrator — a precise, evidence-based follow-up prompt is sent back into the SAME `--session` (continuing that sub-agent's context) rather than starting fresh or patching it inline. This happened twice for #328 and once (so far) for #329.
- **CHANGELOG.md not yet updated, no `.md` commit, no `@oh` review yet** — per the goal's own ordering, these happen only after ALL 9 tasks (#328–#336) are done, not incrementally.
