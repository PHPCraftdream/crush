## Decisions

- Chose variant (2) for P0-1 (drain pending run-queue entries before
  process exit) over variant (1) (reintroduce a live mailbox handoff for
  durable-queue interrupts) — per user's explicit confirmation after my
  recommendation. Rationale: variant (1) would have re-duplicated the
  entire lease/renew/watchdog/ack machinery in a second place and
  reintroduced the exact dual-ownership hazard the FromDurableQueue guard
  was built to close.
- Discovered mid-implementation that a synchronous, in-place
  `DrainSessionNow` call inside `case result := <-done:` was structurally
  wrong (starves `messageEvents`) — chose to restructure into a `finish`
  closure + async `drainDone` channel rather than patch around it, since
  the whole point of P0-1's fix is that the continuation's real output
  must reach the envelope, not just that *something* eventually executes
  it server-side.
- For GLM-5.3 in the web UI: chose to synthesize the model entry inside
  `configureProviders` (fork-owned code) rather than wait for upstream
  catwalk to add it, or ask the user to hand-edit their own
  `providers.zai.models` config — matches the existing precedent (the
  `local-cli` provider is synthesized the same way) and is automatically
  superseded once catwalk/the user's own config provides a real entry.
- Implemented both P0-1 and the GLM-5.3 web UI fix directly (no
  subagent/`/crush` delegation) — consistent with this entire session's
  established zero-trust, self-verified pattern for fixes in
  security/concurrency-sensitive code.
