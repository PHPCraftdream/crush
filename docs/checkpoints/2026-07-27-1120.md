- **#84 (cliprovider, `TestStreamWaitBoundedOnGrandchildHoldsStderr`)**:
  found the reap step's PID file was NEVER written — `BuildArgs` passes bash
  `[flag, script, tmpDir]`, so under `bash -c`'s convention `tmpDir` lands in
  `$0` not `$1`; the script used `"$1/grandchild.pid"`, silently writing to
  `/grandchild.pid` (permission denied) every single run. Fixed to `$0`.
  Also found `$!` under MSYS2/Git-Bash is an emulated Cygwin-style PID, not
  the real Win32 PID `taskkill /PID` needs — added WINPID resolution via
  `ps -a | awk '{print $4}'` before calling taskkill. Added a
  `waitForRemovable(t, dir, budget)` helper (bounded `os.RemoveAll` retry) as
  defense-in-depth. Verified 10/10 clean.
- **#85 (internal/cmd, `TestModelsBump_NonAtomModel_ReportsCleanly`)**: ruled
  out a Go-controllable handle leak (traced `db.ResetPool()` →
  `sql.DB.Close()` → modernc.org/sqlite's synchronous `CloseHandle`, no
  goroutines/finalizers anywhere in that stack; cleanup ordering via
  `t.Cleanup` LIFO already correct). Root cause: Go's own `testing` package
  already retries this exact Windows sharing-violation error but caps the
  retry window at a hardcoded 2s (`testing_windows.go`), which can be
  exceeded under real multi-process contention. Added
  `waitForSQLiteHandleRelease` (rename-in-place probe on
  crush.db/-wal/-shm/-journal, 10s bounded poll) to `isolatedModelsEnv`'s
  shared `t.Cleanup`, benefiting every `models_*` test that uses it, not
  just the one that failed. Verified 20/20 clean plus spot-checks on 3 other
  tests sharing the helper.
- **#86 (mcp, `TestConfigureStdioProcess_CancelTreeKillsOrphanedGrandchild_Windows`,
