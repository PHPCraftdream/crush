## Session summary

Resumed from `2026-08-14-1548.md` (which closed #458, the P0-1 live-continuation
fix, and GLM-5.3 web UI work). This session confirmed the combined CI build for
commit `1cc61c34` went fully green, closed #421/#459, then pivoted to a new
user-reported bug via `/oh`: switching a session's model in the web UI toolbar
was changing the model **globally**, not just for that session.

Root-caused via direct code read (not guessed): `ModelSelector.onSelect`
(web/src/components/ModelSelector.tsx) called `trackModelUsage()` alongside the
correct `setSessionModels()` call; `trackModelUsage` sent WS command
`track_model_usage`, whose handler (`handleTrackModelUsage`,
internal/server/handlers.go) called `store.UpdatePreferredModel(ScopeGlobal,
...)` — writing straight into the global `crush.json`. Worse: `useWS.ts`'s
`message_created` subscriber fired the SAME command on every assistant
message, so the global default silently drifted to whatever session was most
recently active, not just on explicit picks.

While fixing this (task #460), found and fixed two related bugs:
- **#461**: the selector always sent BOTH large+small slots on every switch
  (filling the untouched one from current/default), pinning it against later
  folder/system changes. Also discovered `handleCreateSession`/
  `handleInitializeProject` seeded a NEW session's model columns from the
  merged config AT CREATION TIME — freezing every untouched session's
  inheritance from birth. Both fixed: `session.Service.UpdateModels` changed
  signature from 4 plain strings to `(large, small *ModelSlotUpdate)` with
  nil-means-untouched semantics (backed by a `COALESCE(sqlc.narg(...), col)`
  partial-update SQL query); session creation no longer seeds models at all.
- **#462**: added a WS API (`get_scoped_models` / `set_scoped_model` /
  `clear_scoped_model`) for reading/writing system(global) and
  folder(workspace) scope explicitly, reusing `store.ReadAllModelsAtScope`
  and the same vocabulary `crush models state` already uses.
- **#466**: DB migration (`20260816000001_add_worker_reviewer_to_sessions.sql`)
  + full session/service/coordinator plumbing so worker/reviewer are now
  session-scoped too (previously only large/small were). Investigated deeply
  whether this actually affects sub-agent dispatch: found `buildAgent`/
  `agentTool` build ONE shared `SessionAgent` object at coordinator-construction
  time (config reload), reused for every sub-agent call regardless of session —
  so a session-level worker override needed a NEW per-call resolution path,
  not just DB storage. Added `coordinator.resolveSubAgentModelOverride` and
  wired it into `runSubAgent` via the ALREADY-EXISTING immutable per-call pin
  mechanism (`SessionAgentCall.LargeModel`, the same one task #341/P0-1 built
  for top-level turns) — no shared-state mutation, isolation-tested. Reviewer
  has NO such hook: it's consumed only via `crush run --role reviewer` (a
  whole-run CLI choice), never at sub-agent dispatch time — documented this
  explicitly rather than inventing a fake runtime effect for it.
- **#463/#467**: new `ScopedModelsModal.tsx` (three blocks: System / Folder /
  Session, all four slots, per-scope explicit-vs-inherited display, per-slot
  clear) wired into `ChatToolbar.tsx`'s header; and an "Inherit" entry added to
  `ModelSelector`'s dropdown (`clearSessionModelSlot` in store.ts, using a
  non-null-but-empty `{provider:"",model:""}` payload — distinct from
  null/omitted, which means "don't touch" server-side).
- **#464**: cascade regression tests at both layers — `internal/config`
  (system→folder merge/clear) and `internal/agent` (session override on top of
  an already-folder-shadowed config, and clearing it falls back correctly).
- **#465**: CHANGELOG + README updated (new README section explaining the
  session level of the cascade and the "Default models" modal).

  creation — judged in-scope of "make the cascade actually work" per the
  user's original ask.

  `UpdateSessionModels`/`UpdateSessionWorkerReviewerModels` over dynamic query
  building, to distinguish "don't touch this slot" (nil arg) from "clear this
  slot" (non-nil arg with empty string) at the DB layer, not just in Go.

  for my changes): stopped chasing it after confirming via `git stash` and an
  unrelated-spec test that it's pre-existing and environment-specific, filed
  #468, and proceeded on `tsc`+`build`+code-review confidence instead of
  blocking all frontend work on a broken local E2E harness.
