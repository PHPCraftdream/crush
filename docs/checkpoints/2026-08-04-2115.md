# Checkpoint — 2026-08-04 21:15

## Session summary

Continuation of `2026-08-04-2010.md`, which covered the blocker batch and
the sub-agent-hang root cause. This checkpoint covers the closing `@oh`
review of that batch and the fixes it forced — including two regressions
the batch itself had introduced.

**The closing review held NO-GO and was right to.** It named three real
defects, verified here by direct code read (and, for the first, by
reproducing the reviewer's own probe) before any fix:

1. **P0-C was only half done.** The per-mailbox `stopped` latch stops an
   EXISTING turn loop from taking more work, but nothing stopped a NEW
   owner from appearing. `submit()` never consults the latch, so once
   `CancelAll`'s sweep leaves a mailbox idle the next `Run` claims it and
   runs a full provider turn the finished sweep can never cancel. Worse:
   mailboxes are created lazily and `CancelAll` iterates a COPY of the
   map, so a `Run` for a session id the sweep never saw gets a fresh
   mailbox with `stopped == false` — no race required. Reproduced
   directly: after `hardStop` + `abandonOwnership`, `submit` still
   returns `becomeOwner=true` with a new epoch. Callers that can reach
   `Run` after the sweep are several and real, including the detached run
   this same round's P0-B fix added.
   Fixed with an agent-level one-way `shuttingDown` latch checked in
   `Run` before any session is claimed — the only place that can cover a
   mailbox which does not exist yet — returning an explicit
   `ErrAgentShuttingDown` rather than `(nil, nil)`, since the latter is
   what "queued behind another owner" looks like and nothing would ever
   drain that queue during shutdown.
2. **`interruptAndReplace` reported false success during shutdown.** It
   only checked `state != mbOwned`, so on a hard-stopped-but-still-owned
   mailbox it recorded the replacement and returned `hadOwner=true`; the
   coordinator then skipped its own no-owner path and the web client was
   told "queued" for a payload both drains now refuse. It treats
   `stopped` as "nobody running".
3. **`hardStop`'s doc was factually wrong.** It claimed queued work "is
   already persisted as user messages". It is not: `buildCall` creates no
   DB row, the user message is only written in `runTurn`'s preamble, and
   both `mb.submitted` and the `messageQueue` it drains into are
   process-local. An unstarted prompt IS lost on shutdown. Corrected to
   state the real trade rather than a false guarantee.

**A regression from this round's own P1-B fix**, also found by the
review and confirmed here: `generateTitle`'s fallback wrote
`DefaultSessionName` unconditionally, which was only safe while `runTurn`
waited unconditionally for that goroutine. Bounding the join let an
abandoned title goroutine outlive its turn and overwrite a title a LATER
turn had generated — and since `needsTitle` counts `DefaultSessionName`
as "still needs one", that loops. The fallback now re-reads the session
and only stamps the default if the slot is still empty.

**A process lesson worth recording.** The `/crush` agent working on #296
(P1-C) was writing `internal/agent/mailbox.go` at the same time as I was
fixing blockers in it. It overwrote two of my fixes (the
`interruptAndReplace` gate) and reverted `errors.go` entirely
(`ErrAgentShuttingDown` vanished). This is precisely the concurrent-write
hazard CLAUDE.md warns about for parallel agents; I had treated "agent
works on file X while I work on blockers" as safe because the tasks were
logically separate, which was wrong — they shared a file. The agent was
stopped, its work stashed (see below), and the blocker fixes reapplied on
a clean tree.

## Decisions

- Killed the in-flight P1-C agent rather than letting it finish, once it
  became clear it was overwriting blocker fixes in a shared file. The
  blockers outrank a P1 hardening, and a half-merged `mailbox.go` in the
  most-reviewed file in the repo is worse than a deferred task.
- Stashed its work instead of discarding it — it is substantial and
  likely mostly right — but recorded plainly in the task that it is
  unverified, so a future session does not mistake "an agent wrote it"
  for "it was reviewed".
- Returned an explicit error from `Run` during shutdown rather than the
  silent queue-and-return-nil that the "someone else owns this" path
  uses. Slightly noisier for callers, but the alternative reproduces the
  exact accepted-but-never-executed failure P0-A/P0-B were about.
