Саб-агентские делегирования в этой же сессии регулярно занимали 10-25+ минут — родитель убивал сам факт ожидания, хотя саб-агент работал нормально.

**Три фикса реализованы, протестированы и закоммичены** (без пуша — пользователь явно не просил):
1. `9226cb9a` — `toolStarted`/`toolFinished` в `stream_watchdog.go` теперь принимают `exempt bool`; `agent`-tool вызовы (`AgentToolName`) помечаются exempt и полностью пропускают `toolMaxDuration`-проверку (idle-пауза сохраняется).
2. `608f24f7` — при живом тестировании фикса #1 обнаружен смежный баг: модель (glm-4.7) батчит несколько tool-calls в один шаг (fantasy файрит все `OnToolCall` до выполнения любого из них), из-за чего `toolStartedAt` фиксировался один раз на весь батч и суммарное время нескольких коротких вызовов могло превысить кэп. Исправлено — `toolStartedAt` теперь сбрасывается на каждый `OnToolResult`, если в батче остаются другие незавершённые инструменты.
3. `056c53d0` — при живом тестировании (сборка реального бинарника, запуск через `crush run` с укороченными кэпами) обнаружена ГОНКА: `bash.go`'s ctx-cancellation ветка вызывала `bgManager.Kill(ctx, id)` с УЖЕ отменённым `ctx` в качестве собственного дедлайна ожидания внутри `Kill()` — `select` мгновенно брал ветку `<-ctx.Done()` вместо ожидания `<-shell.done`, из-за чего `Kill()` возвращался мгновенно, не дождавшись реального завершения процесса (асинхронный `taskkill /F /T` через `context.AfterFunc` в `exec_windows.go` ещё не успевал отработать). Исправлено — используется свежий `context.WithTimeout(context.Background(), 5s)` вместо мёртвого `ctx`.
