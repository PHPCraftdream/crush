Launch a new agent that has access to the following tools: glob, grep, ls, view. When you are searching for a keyword or file and are not confident that you will find the right match on the first try, use the agent tool to perform the search for you.

When running as a smart orchestrator with a worker model configured, the sub-agent may also get hands-on tools (edit, multiedit, write, bash, todos, download, fetch, ask_question) to actually perform delegated work, not just search.

If the sub-agent calls its own question tool, this tool call does NOT fail — it returns a normal, successful result shaped like `SUB-AGENT QUESTION (session <id>): <question>`, telling you the sub-agent is paused with its full context intact, awaiting an answer. This is not an error and does not mean the sub-agent crashed; do not redo its work yourself. Decide the answer (or escalate to the operator via your own question tool if it's genuinely not your call), then call this tool again with `resume_session_id` set to the session id from that result and your answer as `prompt`. This continues the SAME sub-agent session with its prior context preserved, rather than starting a new task from scratch. `resume_session_id` must reference a session that was created by one of your own prior `agent` calls — resuming an unrelated session id is rejected.
